<objective>
Turn the live classifier into a per-window pipeline: read binary segments safely, embed with an alignment check, classify every window with the bundled served model, aggregate by the mean of window probabilities into the unchanged legacy `classification`, persist the per-window block, stamp honestly, and serve the new keys additively through /visualize.

Purpose: ML-02 and success criterion 2. CONTEXT "Analysis results and legacy /visualize compatibility" locks the classification aggregation and the unchanged legacy shape; the amendments lock binary transport with a legacy JSON reader during rollout (Q7), the train/serve parity rule ("Production serves only the successor together with reef_audio, never the old weights with new preprocessing") and the stamp extension (stamp_for_model requires reef_audio.SPEC_VERSION). RESEARCH Pitfalls 4, 5 and 9 (DynamoDB types, silently skipped segments, mixed-version stamping).

Planner decisions recorded here (both follow from the parity amendment, which overrides the earlier "accept the old and new segment formats" bullet where they conflict):
- Legacy JSON segments are read and identified, then refused with PREPROCESSING_SPEC_MISMATCH (a retryable, clearly worded ERROR) rather than classified: classifying them with the successor would be the same train/serve mismatch in the other direction. In-flight analyses in the minutes between the classifier and preprocessor deploys (05-17) fail cleanly and can be re-run.
- The served model is bundled in the classifier zip (drift-checked with the code, D-03) instead of overwriting S3 models/, because the currently deployed classifier re-reads S3 models/ every 60 s and would immediately serve successor weights on legacy windows.

D-12 still holds: probabilities are never scaled or withheld. D-13: `visualization` is never repopulated.

Output: rewritten classifier, reef_reference served-model loader, extended stamp guard, router whitelist, package spec code members.
</objective>
