## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Any browser -> /api/client-error/ | Public, unauthenticated POST endpoint; all input untrusted |
| Route handler -> Vercel runtime logs | Logged text is readable by whoever opens the project logs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-12-01 | Information Disclosure | PII, presigned URLs, query strings or tokens reaching logs | high | mitigate | Client and server scrub with the same rules; strict schema with only the eight fields; route is pathname only; unit tests with fake X-Amz-Signature, email and token samples; e2e asserts the posted body is scrubbed |
| T-03-12-02 | Tampering | log injection / forged multi-line entries | medium | mitigate | One JSON.stringify line with a fixed prefix and evt field; newline-free; strict schema rejects unknown fields |
| T-03-12-03 | Denial of Service | log flooding or oversized bodies | medium | mitigate | 4 KB cap (413), per-instance token bucket (429), client cap of 5 per page load and 60 s dedupe |
| T-03-12-04 | Spoofing | cross-site forged reports | low | mitigate | Origin host must equal Host (403); JSON content type forces a CORS preflight for cross-origin browsers; no CORS headers are added |
| T-03-12-05 | Repudiation | visitor told an error was handled when it was not | low | mitigate | No UI at all; copy-claims gate on src |
</threat_model>
