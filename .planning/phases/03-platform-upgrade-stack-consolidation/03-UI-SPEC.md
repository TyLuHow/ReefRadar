# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This is a parity-and-removal contract, not a redesign.** The owner locked "no new visual design until Phase 4" (03-CONTEXT.md). Every value below is either carried unchanged from today's dark palette (`globals.css`, `tailwind.config.js`, `src/types/index.ts`) or is the minimum new surface the phase must add (client error pages). Where a minor visual choice was open, the option closest to today's look was chosen and tagged **[Discretion]**. Anything not stated here stays exactly as it is in the repo.

Sources: 03-CONTEXT.md (locked decisions), REQUIREMENTS.md (PLAT-01/02/03/09/10, DS-07), TECH-LANDSCAPE.md (MapLibre, Plot 0.6.17, Speed Insights), codebase scan of `dashboard-next/src`.

## Map Parity Contract (PLAT-02)

All three Leaflet components and the deck.gl `ReefMap` become `maplibre-gl` + `react-map-gl/maplibre`. Pin versions in the plan (MapLibre 6 is ESM-only and needs WebGL2; TECH-LANDSCAPE P4: use named/namespace imports). **Coordinate order trap:** Leaflet is `[lat, lon]`, MapLibre is `[lon, lat]`; every ported call site needs a test with a known site (e.g. Indonesia lon ~119, lat ~-5 lands in Indonesia, not Antarctica).

### Base layer and attribution (locked: OSM raster, same attribution)

WorldMap and MiniMap use a raster style:

- Source tiles `https://tile.openstreetmap.org/{z}/{x}/{y}.png`, `tileSize: 256`, `maxzoom: 19` (the `{s}` subdomains Leaflet used are not needed by OSM policy).
- Attribution string (WorldMap): `&copy; <a href="https://www.openstreetmap.org/copyright">OpenStreetMap</a> contributors`; MiniMap: `&copy; <a href="https://www.openstreetmap.org/copyright">OpenStreetMap</a>`. **Always visible as text**, `AttributionControl` with `compact={false}`, bottom-right. Styling parity with today: background `rgba(255,255,255,0.8)`, padding `2px 6px`, radius 4px, font-size 10px.
- OSM tile policy: attribution visible (above), no bulk prefetch or scripted tile loading, no tile URL rewriting, no custom User-Agent tricks. The existing `Referrer-Policy: strict-origin-when-cross-origin` header already sends the origin OSM expects; do not weaken it.
- **ReefMap exception [Discretion]:** it already renders a MapLibre vector style (`basemaps.cartocdn.com/gl/dark-matter-gl-style/style.json`, dark) and CONTEXT says "same tiles as today", so it keeps that style URL and the style's own attribution (CARTO / OpenStreetMap contributors), `pitch: 30`. Switching it to light OSM raster would be a visible redesign of the dark map page; the CARTO to OpenFreeMap/OSM question is deferred to Phase 6. Flagged for owner awareness in the hand-off.
- The visual suite already blocks `tile.openstreetmap.org` and `cartocdn.com` with a transparent PNG; keep both patterns.

### Keyboard and ARIA: no worse than today

Today: Leaflet markers are focusable buttons (Enter opens the popup) but announce as "Marker"; deck.gl points have no keyboard access; map pan/zoom keys work on Leaflet only.

- MapLibre keyboard handler stays enabled (arrow keys pan, +/- zoom) on WorldMap and ReefMap. MiniMap keeps it too (harmless, drag stays on).
- Marker DOM element is a `<button type="button">` with `aria-label="{site_id}, {country}, {Status label}"` (never "Marker"); Enter or Space opens the popup; Escape closes it and returns focus to that marker; popup close button labelled "Close popup".
- Map wrapper: `role="region"` with `aria-label="Map of reef recording sites"` (ReefMap: also "Monitoring network map"); legend and overlay controls remain ordinary focusable HTML.
- ReefMap circle layers are canvas-rendered and not individually focusable (same as deck.gl today, so not worse). The accessible per-site alternative (site list/table) is a Phase 6/16 deliverable and is explicitly not claimed here.
- `a11y.spec.ts`: no NEW serious/critical rule vs `tests/baseline/pre-truth/axe/summary.json` on `map`, `sites`, `analyze`. Fewer violations are fine (do not edit the summary except by explicit owner approval).

## Chart Parity Contract (PLAT-02)

**Finding (verify at plan time with `grep -rn "recharts" dashboard-next/src`):** recharts is declared in `package.json` but has **zero import sites** in `src/`, and so does `wavesurfer.js`. Charts rendered today are hand-built: `components/charts/ProbabilityBars.tsx` (HTML bars and stacked bar) and the canvas spectrograms. Therefore:

1. Removing `recharts` (and `wavesurfer.js`, `leaflet`, `react-leaflet`, `@deck.gl/*`) is a dependency-only change with **no chart pixels moving**; `npm ls` must show none of them.
2. `ProbabilityBars` / `ProbabilityStackedBar` **stay as they are** **[Discretion]**: porting hand-rolled HTML bars to Plot would change a user-visible, tested component (`results-components.test.tsx`) for no parity benefit; Phase 9 rebuilds results as search. Do not touch their layout, colours, integer-percentage logic (`toIntegerPercentages`, sums to exactly 100) or the rule that classes absent from the model (e.g. `restored_mid` on the 3-class interim model) are never rendered.
3. A `<PlotFigure>` wrapper (feature module) is built only if a plan task has a real consumer or its own unit test; no dead wrapper and no legacy page changes. If built, it must satisfy the rules below, which also define "Plot parity" for any chart that does get ported later.

`PlotFigure` rules (pin `@observablehq/plot` 0.6.17; `d3-scale`, `d3-array`, `d3-shape`, `d3-format` as individual modules, no `d3` bundle):

| Rule | Contract |
|------|----------|
| Render | client-only; `Plot.plot()` result appended into a ref in `useEffect`; cleanup removes the node; width from `ResizeObserver`; no SSR of the SVG |
| Same meaning | same data, same encodings, same labels as the chart it replaces; categorical order by raw probability descending as today |
| Honest axes | probability axes fixed to domain `[0, 1]` (or `[0, 100]%`), zero baseline, no truncated axes, tick format via `d3-format`; displayed integer percentages come from `toIntegerPercentages`, never re-rounded in the chart |
| Colour | categorical fill from `STATUS_COLORS` via a `color.domain/range`; text fill `var(--text-secondary)`, rules/ticks `rgba(229,225,219,0.1)`; no new hues |
| Type | Inter (inherit), 12px labels, tabular numerals for values |
| Motion | none (no transitions, no entrance animation) |
| ARIA | root SVG gets `aria-label` (what it shows) and `aria-description` (the takeaway, e.g. "Degraded 62%, healthy 25%, restored (early) 13%"); decorative marks (gridlines, frame) `ariaHidden`; each datum mark an `ariaLabel` channel ("Degraded: 62%") |
| Keyboard | Plot has no built-in keyboard navigation; every figure is wrapped in `<figure>` with `<figcaption>` and a visually hidden `<table>` of the plotted values (the keyboard/screen-reader equivalent). Interactive tooltips are not introduced this phase |
| Empty / single / many | empty data renders the caption plus "No data to plot." and no SVG; one value renders one mark (no misleading scale); many values truncate with the caption stating the cutoff |
| Visual baseline | any shipped Plot chart appears in the baseline diff review like every other change |

## Visual Baseline Review and Acceptance Protocol (Success Criterion 1)

Facts: 33 Linux baselines (11 states x 1440/1024/390) generated in `mcr.microsoft.com/playwright:v1.63.0-noble`; `toHaveScreenshot` uses `maxDiffPixelRatio: 0.01`, `animations: 'disabled'`; canvases and maps are hidden (`visibility: hidden`) so canvas pixels are not in the baseline. Consequence: the baseline can barely see the vitality removal or the map port, so the protocol adds a review-only capture.

1. **Pin "before".** Record `BEFORE_SHA` (the last commit before any Phase 3 code change) and the CI run id where the `visual` job passed 33/33 at that SHA. The committed PNGs at `BEFORE_SHA` are the "before" set; never regenerate them.
2. **Upgrade commits stay baseline-neutral.** Each step (Next 15, Next 16, React 19, codemods) is its own commit and must keep the `visual` job green against the unchanged baselines. If a step needs a baseline change, regenerate and log it separately with its cause; never batch an upgrade diff with a vitality/map diff.
3. **Regeneration path is CI only.** Push the UI change (the `visual` job is expected to go red), then run the CI workflow with `workflow_dispatch` `update_snapshots=true` (do not push while it runs; concurrency cancels in-progress runs), download the `visual-snapshots` artifact, inspect, and commit it unchanged in a follow-up commit referencing the dispatch run URL and the SHA it ran at. Windows renders are never committed.
4. **Expected changes (everything else is a regression to fix, not to regenerate).** Certain: `experience-compare` x 3 widths (slider track/thumb). Possible, each needing a one-line justification in the review page: any state where a removed decorative canvas shifted layout (none is expected: they are absolute/fixed), map overlay HTML (legend, rank badges, loading panel) if z-index or position changed, the new `error.tsx`/`global-error.tsx` (not in the 11 states; covered by RTL unit tests, see UI Considerations).
5. **Review page for the owner (like Phase 1).** A script (`scripts/build-visual-review.mjs`, no new dependencies) emits `docs/deploy/PHASE-3-VISUAL-REVIEW.md` plus a static `docs/deploy/phase-3-visual-review/index.html` (before/after images side by side, with a "difference" toggle using CSS `mix-blend-mode: difference`), listing all 33 states with: status (identical / changed), cause, owner decision column (pending / accepted / rejected). Images are copied into `docs/deploy/phase-3-visual-review/{before,after}/`. Evidence style follows `docs/deploy/PHASE-1-EXIT.md` (run URLs, SHAs, no tokens or presigned URLs).
6. **Review-only unhidden captures** (not gating, not committed as baselines, uploaded as a CI artifact via a `PW_REVIEW=1` mode or sibling spec): 1440px captures with canvases and maps visible for `map`, `sites`, `analyze` (with a result so `MiniMap` shows), `experience-compare`, at `BEFORE_SHA` (Leaflet/deck.gl/vitality) and at the Phase 3 head (MapLibre, static). Tiles stay mocked with the transparent PNG so markers, popups and overlays are comparable. These feed the same review page under "Map and canvas changes".
7. **Acceptance gate.** The owner signs off in the review page (decision column) for every changed or justified-possible state and for the unhidden map captures before the phase is marked verified. Rejected rows reopen the work. Record the sign-off and date in the phase verification file.
8. **Other gates unaffected.** Route e2e, axe regression (no NEW serious/critical vs the pre-truth summary), unit tests, the contract fence, and the new legacy-import fence must stay green; the visual baseline update does not relax any of them.
