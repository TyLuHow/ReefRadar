<objective>
Move dashboard-next from Tailwind 3.4 to Tailwind 4.3.3 (CSS-first) without changing one legacy pixel.

Purpose: Tailwind 4 `@theme` is the only way to get the single CSS token source DS-01 asks for (CONTEXT: "Tailwind v3 → v4 CSS-first"). This plan is the highest-risk change in the phase, so it lands alone (CONTEXT: "Tailwind v4 lands alone first ... Nothing else lands until that is green in CI").
Output: Tailwind 4 build, five tested mitigations, a legacy-baseline hash guard, a computed-style fingerprint proof recorded in the SUMMARY, the v4 source-coverage test, a hover probe.

Scope exception (file count above 15): the official upgrade tool rewrites the config, the stylesheet and about 30 source files in one atomic step, and the migration is only meaningful (and only provable against the 33 baselines) as a whole. Splitting it would land a half-migrated, unbuildable tree. This plan therefore stays one plan and lands alone.

Gate for the orchestrator (not a task): after this plan's commits are pushed, the CI `visual` job must pass with the 33 baselines untouched before 04-02 or 04-03 starts. Do not run the `update_snapshots` dispatch for this plan.

Rollback path if the CI `visual` job fails:
1. Download the `playwright-report-visual` artifact and list which of the 11 states and widths differ.
2. Compare those states in the local fingerprint diff (Task 3) and in the RESEARCH "Pattern 1" mitigation table; iterate mitigations in `src/app/globals.css` only (literal colours, `@layer base` placement, line-heights, `/srgb` gradients, cursor rule). Never move `.glass-panel`, `.glass-button`, `.heading`, `.hero-text` or `.mono` into a cascade layer.
3. Push the fix and re-run CI. Never regenerate or copy over any file in `tests/e2e/visual.spec.ts-snapshots`.
4. If three iterations do not converge, `git revert` this plan's commits (back to Tailwind 3.4.7, tree green) and stop the phase with the differing states listed.
</objective>
