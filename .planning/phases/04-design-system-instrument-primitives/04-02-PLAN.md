Planner decisions applied in this plan (settled conflicts and discretion, CONTEXT "Claude's Discretion"):
- Token names follow 04-UI-SPEC "Token Architecture" (`ground`, `panel`, `ink`, `muted`, `rule`, `hab-*`, fonts `display`, `body`, `data`, `numeral`); the status values are the UI-SPEC contract (CONTEXT "Decisions after research: Status palette").
- Raw per-direction variables are `--dir-<name>`; Tailwind sees them only through `@theme inline` (RESEARCH "Pattern 2"). With `@theme inline` no `--color-*` variable exists at runtime, so any CSS-variable string in TS or SVG uses `var(--dir-<name>)`.
- Added tokens the UI-SPEC prose needs but its table lacks: `playhead` (#FFFFFF, all), `inverse` (#FFFFFF, all), `on-inverse` (atlas #0D0F14, nocturne #0B0D12, poster #0A0A0A), `band-control-hover` (#FFFFFF, all), `band-control-pressed` (#D9DCE4, all), `block-alt` / `on-block-alt` (poster #FF6FB1 / #0A0A0A; atlas and nocturne equal their `accent-block` / `on-accent-block`), `--max-blocks` (1, 1, 3).
- No named `--spacing-*` keys: they would collide with legacy `max-w-md` style utilities. Spacing uses Tailwind's default numeric steps (p-1 = 4px ... p-24 = 96px), which equal the UI-SPEC 4 px scale; direction-dependent spacing uses `--space-block` and `--gutter` through arbitrary values.
- Fixed and fluid type sizes are in rem with the UI-SPEC vw term kept, so browser text zoom still scales them (WCAG 1.4.4); see the size list in Task 2.
- Font CSS variables come from `next/font` calls made later in `src/app/dev/layout.tsx` (plan 04-06) with these exact names: `--font-newsreader-italic`, `--font-newsreader-roman`, `--font-hanken`, `--font-spline-mono`, `--font-archivo-black`.
