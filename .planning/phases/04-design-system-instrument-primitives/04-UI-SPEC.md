# Phase 4 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**This is a new-surface contract.** Phase 4 builds the design system and the instrument component kit. It does not redesign any legacy page. Legacy routes keep their current dark look and the 33 Linux visual baselines must not change (see "Legacy isolation").

Sources: 04-CONTEXT.md (owner decisions: direction C "Atlas", data colour option 1, expressive range, alternative directions), REQUIREMENTS.md (DS-01 to DS-06, DS-08), ROADMAP.md (Phase 4 success criteria), REDESIGN-THESIS.md and TECH-LANDSCAPE.md (pinned versions, keyboard and a11y principles), 03-UI-SPEC.md (format precedent), the owner-approved board sources (`gen.py`, `gen2.py`, read-only, not copied into the repo), and a scan of `dashboard-next/`.

Nobody was available to answer questions. Every open choice was decided and is logged in "Decisions and Assumptions" at the end. Numbers marked "computed" were produced by a script (WCAG 2.x contrast, CIEDE2000, Machado et al. 2009 CVD matrices at severity 1.0, the same matrices `gen.py` uses).

## Legacy isolation (hard constraint)

1. **33 baselines stay byte-for-byte the same set and pass unchanged** (11 states x 1440/1024/390, `maxDiffPixelRatio 0.01`). A diff in any of them is a defect to fix, never a regeneration. A CI guard asserts the committed baseline file list for `visual.spec.ts` is unchanged by Phase 4 commits.
2. Legacy tokens keep their names and values: `abyss`, `depths`, `bg-surface`, `bone`, `ochre`, `dusty-rose`, `pale-gold`, `muted-tan`, `warm-gray`, `warm-amber`, `glass-*`, `status-*`, plus the `--bg-*`, `--glass-*`, `--text-*`, `--freq-*`, `--status-*`, `--accent-*` CSS variables, `.glass-panel`, `.glass-button`, `.heading`, `.hero-text`, `.mono`. A unit test fails if any new token name equals a legacy name.
3. `STATUS_COLORS` in `@/types` and `@/lib/utils` helpers stay untouched and legacy-only. The new palette has one source (`tokens.css`); do not add a third mapping for legacy code.
4. Tailwind v3 to v4 migration must be baseline-neutral. Run the official upgrade tool, then diff the baselines. Known v3 to v4 behaviour changes with legacy exposure that need compatibility shims in `legacy.css` if any baseline moves: default border colour (now `currentColor`), default `ring` width and colour, renamed `shadow-*`, `rounded-*`, `blur-*` and `backdrop-blur-*` steps (legacy uses `shadow-sm` in 3 files, bare `rounded` in 36, `backdrop-blur` in 2, `blur-sm` in 1), `outline-none` (2 files), `border-opacity-*` (2 files), `flex-grow` and `flex-shrink` (16 files). Do not override Tailwind's default `--radius-*`, `--shadow-*` or `--font-sans`/`--font-mono` namespaces: that would restyle legacy.
5. `tailwind.config.js` and `postcss.config.js` (autoprefixer) go away. `tests/unit/tailwind-content.test.ts` is replaced by a test that asserts `src/features` and `src/app` are covered by v4 source detection (add an explicit `@source` for `src/features`).
6. **Global legacy rules must not leak into new surfaces.** New surfaces live inside a root element with `data-surface="instrument"`. Inside it, these legacy globals must not apply (mechanism is the plan's choice: cascade layers or scoped resets; behaviour is fixed and verified by a Playwright computed-style test on `/dev/fixtures`):

| Legacy global | Required behaviour inside `[data-surface="instrument"]` |
|---------------|--------------------------------------------------------|
| `body` `bg-abyss text-bone`, Inter class | The surface paints its own ground over the full viewport, including overscroll (`html:has([data-surface="instrument"]) body` sets ground and ink). Legacy routes unchanged. |
| Universal `*` 150 ms transition rule | Does not apply. Transitions come only from component classes using `--duration-*` tokens. |
| Global `:focus-visible { outline: 2px solid #cd853f }` | Replaced by the direction's focus token. |
| `::-webkit-scrollbar` dark track and thumb | Overridden for instrument pages (`html:has(...)`): track `panel`, thumb `rule-strong`. |
| `scroll-smooth` on `<html>` | `scroll-behavior: auto` on instrument pages. |
| `.glass-*`, `.heading`, `.hero-text`, `.mono` | Never used in `features/ui` or `features/instrument`. |

## Token Architecture

One CSS file defines everything. TypeScript never redefines a value: it reads resolved custom properties (`getComputedStyle`) for the two consumers that cannot use `var()` (MapLibre paint, Observable Plot colour scales), and tests parse the CSS file directly.

**Semantic token contract (binding).** Every component reads only these names. No component names a raw hex, a font family, a radius in px, or a direction. A test (`semantic-tokens.test.ts`) scans `features/ui`, `features/instrument` and `app/dev` for hex literals (`#rgb`, `#rrggbb`), `font-family`, `border-radius` px values and `data-direction` branches, and fails on any outside `tokens.css` and the status-shape geometry module.

**Directions.** A direction is one token set. The attribute `data-direction="atlas|nocturne|poster"` on the `[data-surface="instrument"]` root selects it. Default: `atlas`. Components never branch on direction. All three directions obey the integrity rules, the status shapes, text contrast 4.5:1, non-text contrast 3:1, 44 px touch targets and reduced-motion rules.

## Typography

Weights: exactly two, **400 and 600**, in every direction. Archivo Black is a single-weight face (400) and counts as the poster display face, not a third weight. Board weights of 500 map to: wordmark 600, mono ids 400.

Fixed sizes (px) and roles. Line-height ratio in the last column.

| Role | Size | Family | Weight | Line height |
|------|------|--------|--------|-------------|
| Eyebrow, axis labels, chips, colourbar labels | 12 | data, uppercase, tracking 0.1em (axis labels not uppercase) | 400 | 1.5 |
| Small (meta, captions, notes, table secondary) | 14 | body | 400 (600 for emphasis) | 1.5 |
| Body, controls, nav, table cells | 16 | body | 400 (600 for emphasis and status labels) | 1.5 |
| Lead (card titles, mono ids small, dialog titles) | 24 | display (titles) or data (ids) | 400 | 1.2 |
| Wordmark, mono id medium, large timecode, slot sub-readouts | 28 | display (wordmark, 600), data (ids and timecode, 400) | 400 / 600 | 1.1 |
| H2 (compare and section headings, accent-block lead); also the `large` Transport timecode (data family, tabular) | 40 | display (H2) or data (timecode) | 400 | 1.1 |
| Mono id large (inspector, selected site, hero timecode) | 44 | data | 400 | 1.1 |

Fluid display sizes (`display-m`, `display-l`, `display-xl`, `numeral`) are the per-direction `clamp` values in the token table. Phone display minimum is the `clamp` lower bound (56 for Atlas `display-xl`). Slot letters ("A", "B") are 96 px serif italic (Atlas) at desktop and 64 on phone, and follow `--font-display`.

Rules:

- Every screen has exactly one `h1`, set in a display tier. Section `h2` use `display-m` or the 40 px H2 role.
- Eyebrow is 12 px (the accepted Listen, Compare and Explore boards use 12; the first inspector board used 11; the larger size is kept for legibility, A3).
- Numbers and identifiers (site ids, timestamps, counts, dB, probabilities) use `font-data` with tabular numerals. Very large counts use `numeral` in `font-numeral` with a 16 px label beside them (max 12 characters wide).
- Negative numbers use the true minus sign (U+2212). Ranges read "0 to 8 kHz". Units have a space ("30 s", "16 kHz", "-47 dB" with U+2212).
- Links: `accent`, underlined (1 px, offset 2), hover colour `ink`. Underline is never removed.
- Site ids wrap at underscores (`<wbr>` after `_`) and use `overflow-wrap: anywhere`. Real ids reach 22 characters (`irma_western_dry_rocks`).
- Sizes in use on one screen are bounded in practice by roles above; the system defines a 7-step fixed scale plus the fluid display tier because the owner accepted the expressive range (A3).

## Color

Atlas values shown (the default). Other directions: "Direction token sets".

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `ground` `#FFFFFF` | Page background, listbox and table rows |
| Secondary (30%) | `panel` `#F1F2F6` | Flat panels (no border, no shadow), compare control strip, selected collection rows |
| Accent (10%) | `accent` `#4338CA` | See reserved list |
| Destructive | none | No destructive hue exists (A10). A destructive action is marked by its verb and a confirmation dialog, never by colour. |

Accent reserved for: (1) the current navigation item (text and 2 px underline), (2) text links (underlined), (3) the focus ring on `ground` and `panel`, (4) the single `accent-block` surface per screen (fill `#4338CA`, white text) and, inside it, a white inverse button, (5) the selected-site ring on the Explore scatter (3 px, `accent`). Nothing else. Accent is never a status mark colour, never a bar fill, never a hover fill. Status colours are never used as accent, text, links, borders or fills of non-data elements.

Computed separation between accent and the two blue status tones (they are both blue family): accent `#4338CA` against `hab-healthy` has CIEDE2000 of 15.7 (normal), 13.2 (deuteranopia), 14.3 (protanopia), 12.5 (tritanopia); against `hab-restored-mid` 23.1, 11.1, 12.5, 16.2. That is why the rules above forbid accent on marks and status on text.

Dark wells (`well` `#0B0D12`) hold spectrograms and waveforms only (plus their axis labels and transport). Status marks never sit inside a well or a band or on any block surface; they sit on `ground` or `panel`, or on a white chip.

### Spectrogram colour scale (DS-03)

- **Scale:** magma, 256-step lookup table, perceptually uniform and CVD-safe (matplotlib colormaps are CC0; credit Nathaniel J. Smith and Stefan van der Walt in the module header). Stops for reference: 0 `#000004`, 0.25 `#51127C`, 0.5 `#B73779`, 0.75 `#FB8861`, 1 `#FCFDBF`. Identical in all three directions.
- **Level:** `dB = 20 log10(|X| / |X|ref)`, clamped to `[floor, 0]`. Default `floor = -80`. `ref` is the loudest bin of the clip shown (`self`), or one `ref` shared by several wells (`shared`, used in compare). Levels are relative, not calibrated sound pressure; every well says so.
- **Analysis:** 1024-point Hann window, hop 256 (A6). Frequency axis is linear from 0 to Nyquist (`sampleRate / 2`; 8 kHz for the 16 kHz excerpts). The caption always prints the parameters actually used.
- **Colourbar:** 12 px thick, same length as the well height (vertical) or 220 px wide (horizontal, hero and phone). Labels `0 dB` at the bright end, `-40` at the middle, `-80` at the dark end (hero shows end labels only). Caption: "Level, dB relative to the loudest bin."
- **Documented next to the component:** the module header and the fixtures Spectrogram section print the table above (scale, floor, reference, window, hop, axis).

## Motion

Motion exists only for continuity. With reduced motion requested, nothing animates.

| Motion | Where | Duration and easing | Reduced motion |
|--------|-------|---------------------|----------------|
| Selection change | Toggle, listbox, table row, legend row fills | `--duration-fast` 120 ms | instant |
| Overlay in and out | Dialog, Sheet, Popover, Tooltip, command palette | `--duration-base` 200 ms, opacity (Sheet also translates 24 px) | instant |
| Layout morph | Legend or band reorder, geography to sound-space (Phase 6) | `--duration-morph` 400 ms, transform only | instant |
| View transition | Content swap on selection (`<ViewTransition>`) | `--duration-view` 200 ms crossfade | none |
| Playhead sweep | Spectrogram playhead while playing | per frame (`requestAnimationFrame`), no CSS transition | steps 4 times a second, no interpolation |
| Spectrogram scroll | Hero and long clips: image pans left while the playhead stays at 22% of the width | per frame while playing | pages: the image advances one visible window when the playhead reaches the right edge |
| Crossfade | A/B crossfader: the quieter well dims (opacity 1 to 0.45) as the slider moves; audio gain ramps 50 ms | 120 ms | the dim switches at the 50% point, no ramp on the visuals |

Rules:

- `--ease: cubic-bezier(0.2, 0, 0, 1)`. Durations are tokens. `@media (prefers-reduced-motion: reduce)` and `[data-reduced-motion="true"]` (fixtures toggle) set every `--duration-*` to `0ms`, disable `<ViewTransition>`, stop canvas loops and set `scroll-behavior: auto`.
- No loop runs while idle: every `requestAnimationFrame` loop is owned by a mounted, playing, visible component (paused on `visibilitychange` hidden and when scrolled off-screen with `IntersectionObserver`).
- No shimmer, pulse, spinner, parallax, ambient or decorative animation. Loading is a static skeleton plus words.
- Verification: a Playwright test with `reducedMotion: 'reduce'` asserts `document.getAnimations().length === 0` on every fixtures section and that computed `transition-duration` is `0s` for every element inside the surface; a second test asserts no frame callbacks are scheduled while paused.

## DS-04 Primitives (React Aria Components)

Common rules for every primitive in this section and the next:

- States by RAC data attribute: `data-hovered`, `data-pressed`, `data-focus-visible`, `data-selected`, `data-disabled`, `data-invalid`. For static screenshots the fixtures route forces a state with `data-force-hover`, `data-force-focus` and `data-force-pressed`, which the same CSS treats as the real attribute.
- **Hover:** fill moves to `panel-hover` (on `ground`) or `control-hover` (on filled controls). No movement, no scale, no shadow.
- **Focus-visible:** `outline: var(--focus-w) solid var(--color-focus)`, offset 2 px (offset -2 px, inset, for items flush with neighbours: table cells, listbox items, toggle segments, window cells). Inside wells and bands `focus-on-well`; inside an accent block `focus-on-accent`. Never removed, never a box-shadow (so forced-colours mode keeps it).
- **Pressed:** `control-pressed` on filled controls, `selected` on panel controls.
- **Disabled:** text and border at `rule-strong` lightened 40% toward `ground`, fill `track`, `cursor: not-allowed`, no hover, `aria-disabled`. Disabled controls stay in the tab order only if they explain themselves with a tooltip; otherwise they are skipped.
- **Selected (compact controls):** `control` fill with `on-control` text. **Selected (collections):** `selected` fill, a 3 px `ink` bar on the inline start edge, semibold text.
- **Control outline on light surfaces:** 1 px `ink` for secondary buttons and toggle segments; `rule-strong` for slider tracks and baselines.
- Every primitive is controlled and uncontrolled per RAC conventions, accepts `aria-label` or a visible label, and renders in the fixtures route in every state listed.

- RAC `TooltipTrigger`, `Tooltip`. Opens after 300 ms hover or immediately on keyboard focus; closes on blur, pointer leave and `Escape`. `control` fill, `on-control` text 14, padding 8 12, max width 280, offset 8, no arrow, radius `--radius-control`.

## DS-05 Instrument Primitives

Shared building blocks (used by several primitives):

- **StatusMark.** Shape plus colour (`hab-*`), sizes 12, 16, 20, 24, outline per rule. `aria-hidden`.
- **R-LABEL (assigned versus inferred).** Anything assigned by a dataset's authors ("reference label") carries a solid 1 px `ink` left rule and the eyebrow "REFERENCE LABEL". Anything inferred by the model ("model reading") carries a dashed 1 px `ink` left rule and the eyebrow "MODEL READING". The difference is never colour alone. Inspector, CompareRow and ProbabilityBar all use it.
- **Skeleton.** Static block, radius `--radius-surface`, fill `track` on `ground`, `panel-hover` on `panel`, `well-raised` in wells. Sized to the final content so nothing shifts.
- **BandSection.** A full-bleed section on `band` with `on-band` text. It can carry the eyebrow, a `display-xl` headline and a large Transport. It may contain a hero Spectrogram edge to edge.
- **AccentBlock.** One solid surface: `accent-block` fill, `on-accent-block` text, padding 32, no radius, no border. Holds a 40 px serif lead (italic in Atlas), one 16 px sentence and one Inverse button. **At most one per screen** (Poster: three block surfaces). A development-only check logs an error if a route renders more than the direction allows.
- **Stat (numeral).** A `numeral` value with a 16 px label beside it, baseline aligned. The value is computed from data, never typed.

### WindowStrip

A row of cells aligned under the spectrogram's time axis: cell k covers [5k, 5k+5) s. It sits on `ground` or `panel`, directly under the well, never inside it.

- Cell: 44 high, 1 px gap. Fill is the reading's status colour at opacity `0.20 + 0.80 x p` where `p` is the model's probability for that class, as returned (not a calibrated confidence). Centre glyph: the status shape, 16 px, **white fill with a 1 px `ink` outline** (readable on every fill from 0.20 tint to full strength).
- Can't tell (abstain): fill `track` with 45-degree hatching (1 px `rule-strong` lines every 6 px) and a hollow ring glyph. No reading: 1 px dashed `rule-strong` outline, no fill.

### StripPlot (Observable Plot via `PlotFigure`)

Three variants share the status shapes, the ink outline, the honest-axis rules from Phase 3 (no truncated probability axes, a stated axis start when a value axis does not begin at zero) and the text-plus-table alternative.

**`strip` (default).** One row per status in ordinal order, one mark per site, deterministic dodge so every mark is identifiable. Row labels carry computed counts ("Degraded 15"). A query marker ("This recording") is an `ink` cross with a label. Hover or focus on a mark shows a tooltip "ind_H1 · Healthy · 0.823". Selected mark: ring 2 px `ink`, size 24. Caption: "{measure} for {n} reference sites, one mark per site." Note when the axis does not start at zero: "Axis starts at {min}, not zero."

**`paired` (dumbbell, two-recording comparison).** One row per measure (fixture: three bands "0 to 1 kHz", "1 to 4 kHz", "4 to 8 kHz"), two 24 px marks per row (A's status shape and B's), joined by a 5 px `ink` bar over a 1 px `rule` baseline. Right column "{a} / {b} dB" in mono. Axis ticks every 5 dB, 12 px mono, with the unit. Legend under the heading: the two marks with "A · {site_id}" and "B · {site_id}". Footnote: "Mean level in each band over these two {duration}-second excerpts, in dB relative to the loudest bin across both. One excerpt per site; this describes two clips, not a finding about the sites." The values are computed from the real WAVs with the same STFT.

**`scatter` (site scatter).** Inline SVG (or Plot `dot`) over the projection coordinates in the contract. Every mark has the ink outline; status shapes at 20 px; the selected site gets a 24 px mark plus a 3 px `accent` ring (44 px diameter) and its id set on the plot in 24 mono, left of the ring. Country names are set on the plot in 24 `display` italic at each country's centroid with a 6 px `panel` halo (`paint-order: stroke`). Axes: zero lines in `rule`; labels 12 mono "COMPONENT 1 · {pct}% OF VARIANCE" and "COMPONENT 2 · {pct}%" read from the projection's explained variance. The projection caveat is printed with it, computed: "The plane shows {cumulative}% of the variation, so near here does not mean similar in sound." Only acoustic-reference sites are plotted (those with projection coordinates); the caption says how many.

Alternative and keyboard: every StripPlot is a `<figure>` with `<figcaption>` and a **visible "Show as table" disclosure** (button with `aria-expanded`) that lists the plotted values (site, status, value). Marks are not individually focusable; any pointer selection must have a keyboard-operable equivalent in the same view (the table or a Listbox), and the primitive's `onSelect` is the only selection path.

## The `/dev/fixtures` Route (DS-08)

**Gate.** The route exists in `next dev` and in builds made with `ENABLE_DEV_FIXTURES=1` (CI test builds). In any other build (production, Vercel preview without the flag) it calls `notFound()`. It is never linked from navigation, sitemap or any page, sends `noindex`, and its data modules load by dynamic import inside the gated route so they are absent from other bundles. An e2e test builds without the flag and asserts a 404 and that no fixture data string appears in the client bundles.

**URLs.** `/dev/fixtures` (index with every section) and `/dev/fixtures/[section]` (one section alone, for isolated screenshots and axe). ## Copywriting Contract

Voice rules: plain and direct, sentence case, no exclamation marks. Say "reading" or "model reading" for model output and "reference label" for what dataset authors assigned. Never "diagnosis", "diagnose", "health score", "AI", "real-time" or any phrase on the banned list in `tests/unit/copy-claims.test.ts` (that gate scans `src/**`, so counts like the site total are always computed, never typed). Times are recorder-clock ("timezone unverified"). Probabilities are integers that sum to 100. Every audio or derived-data surface shows dataset, DOI and licence.

| Element | Copy |
|---------|------|
| Primary CTA (phase) | No screen-level CTA (no user-facing flow ships). Component actions: "Play", "Pause", "Replay", "Retry", "Close", "Clear filters", "Copy request id". Inverse button on the accent block (Listen composition): "Place a recording". |
| Empty state heading | Pattern "{What is missing}." Examples: "No recording selected", "No windows yet.", "No model reading.", "No values to plot.", "No rows match.", "No sites to show.", "No bands are defined for this recording." |
| Empty state body | Pattern "{Next step}." Examples: "Choose a site or a clip to see its spectrogram.", "Windows appear after the recording has been analysed.", "A reading appears after the recording has been analysed.", "Adjust the selection to include at least one site.", "Clear the filters to see all rows." |
| Error state | Pattern heading "{What failed}." plus body "{What to do next}." Examples: "Audio could not be loaded." "Check your connection, then try again."; "The spectrogram could not be drawn." "The audio and any readings are unaffected. Reload the page to try again."; "The table could not be loaded." "Reload the page to try again."; "Provenance could not be loaded." "Try again, or open Methods and limits." With a request id: "Request id: {id}" and a "Copy request id" button. |
| Destructive confirmation | No destructive action ships in this phase. The pattern (fixture of `alertdialog` only): title "Discard this comparison?", body "The clips and their levels will be removed from this view.", actions "Keep comparison" (initial focus, secondary) and "Discard comparison" (primary). Verb plus noun, no hue, no "Are you sure". |

## Decisions and Assumptions

| ID | Decision or assumption |
|----|------------------------|
| A1 | shadcn is not initialised (reason under Design System). Nobody was available to confirm; revisit only if the owner asks for a registry. |
| A2 | Final status hexes are the computed values above, not the mockup hexes. All five changed together because moving only the mid tones left a pair under 8 CIEDE2000 under deuteranopia. The mockup's ink-outline fallback is kept as the universal outline rule. |
| A3 | Type sizes: the accepted boards use many sizes. The contract fixes a 7-step fixed scale plus a fluid display tier. Eyebrow is 12 px (boards) rather than 11 px (first board). Body is 16, merging the boards' 13/14/15. Weights 400 and 600 only; board weights of 500 map to 600 (wordmark) and 400 (mono ids). |
| A4 | Board values not on the 4 px grid were snapped (bars and colourbar 10 to 12, well padding 14 to 16, spacing list above). |
| A5 | Spectrogram renderer is Canvas 2D (deterministic for screenshots, enough for 30 s clips). WebGL2 is deferred behind the same props. |
| A6 | FFT 1024-point Hann, hop 256. The caption prints the parameters actually used, so a later change cannot silently mislabel. |
| A7 | ProbabilityBar fixtures use a one-time read-only capture of the live ind_H1 analysis. If it cannot be retrieved, the repository test fixture is used and visibly marked as a test fixture. The abstain state is forced and labelled "State forced for review" because no real abstain output exists. |
| A8 | BandToggle fixtures use an equal three-way split of the clip's band, labelled as a fixture. |
| A9 | The three owner fonts are kept exactly; they load through `next/font/google` in the new-surface layout only. Archivo Black (poster) is `preload: false`. |
| A10 | No destructive hue. A red would sit close to the degraded brown under protanopia and deuteranopia. |
| A11 | Motion is CSS plus RAC data attributes plus `<ViewTransition>`; no new motion library. |
| A12 | The bar track is `track`, backed by a 1 px `rule-strong` baseline, because the lightest status tone (restored_early) measures 2.94 against `#E9EBF1`; the baseline and the integer label carry extent and value. |
| A13 | The fixtures gate is the env flag `ENABLE_DEV_FIXTURES=1`; the flag name is plan discretion. |
| A14 | Under reduced motion the playhead still advances (it is state, not decoration) but in 4 Hz steps without interpolation; scroll becomes paged. |
| A15 | `ClipCard`, `StatusBand`, `Stat`, `AccentBlock` and `BandSection` are added to the DS-05 list because the accepted expressive boards use them and they have no other home. `CompareDeck` is the composite of two or three CompareRows with a shared control strip. |
| A16 | Nocturne and Poster were designed by the researcher to differ strongly from Atlas and from each other (lightness, display face, rule weight, control shape, density, colour). The owner may reject, rename or replace either; the token contract makes that a one-block change. |
| A17 | Nocturne ships its own dark-ground status palette because the light palette fails 3:1 against dark panels (healthy 1.69). Poster keeps the light palette (its panel `#F2F2F2` still passes). Magma and the wells are unchanged in all directions. |
| A18 | Page gutters follow the accepted boards (48 at desktop, max width 1440) rather than the first board (32, 1280). |
